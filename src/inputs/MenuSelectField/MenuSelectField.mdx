## Usage

Use `MenuSelectField` when a filter accepts one value. It takes `value` and calls `onSelect(value, option)`. Choosing an option closes the menu, and the selected row shows a check. A menu longer than `searchOptionLimit` includes a search field. Pass `onSearch` when the list is too large to hold: the search field is always shown, the debounced text is passed to `onSearch`, and the menu lists the `options` the caller returns. Closing the menu calls `onSearch("")`. Keep the current selection in `options` so its label stays.

Options default to `option.id` and `option.name`. Pass an array, or `{ current, load, options }` to load the list the first time the menu opens. `getOptionMenuLabel` customizes the row. The closed field and the option's accessible name still use `getOptionLabel`. Search matches that string, plus any text from `getOptionSearchText`, unless `onSearch` is set.

Pass `getChildren` when options form a hierarchy. The menu lists every node, indented, with no chevrons. A row with children is semibold; a leaf is regular. The selected row shows a check. The closed field shows the path to that option, joined with ` > ` — for example, `Bath 207 > Walls > Drench`. Sorting stays off unless `autoSort` is set, so the tree keeps the order it was given.

Plug into `@homebound/form-state` with `BoundMenuSelectField`.

On a wide screen the menu is a popover anchored to the bottom-left of the field. It is as wide as the field, and at least 320px. On a small screen it is a bottom sheet.

See [Select fields (new)](?path=/docs/inputs-select-fields-new--docs) for shared implementation details and remaining work.
