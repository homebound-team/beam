## Usage

Use `MenuSelectField` when a filter accepts one value, `MenuMultiSelectField` when it accepts several values, and `MenuTreeSelectField` when those values are nested. Menus longer than `searchOptionLimit` keep search inside the menu, so the closed filter stays compact. Pass `onSearch` to query a list that is too large to hold, such as projects: the caller replaces `options` from the debounced text. A selection the field has already shown stays a pill when that list omits it. On a wide screen the menu is a popover anchored to the field's bottom-left. It is as wide as the field, and at least 320px. A multi select lists each selected option as a pill above that search field. A tree lists its `selectionDisplay` bucket, the same options as its count badge. The pills stay on one line until expanded, and they scroll inside the menu.

These fields share their trigger chrome, searchable menu, option rows, desktop popover, mobile bottom sheet, and form-state integration. `options` can be the full list, or `{ current, load, options }` so a long filter list loads the first time the menu opens. Pass `proposedValue` (single) or `proposedValues` (multi) for AI mode, matching the other fields. Use the child pages and their Examples stories for the closed field. Open-menu behavior is under Menu Behavior. Single Selection, Multi Selection, and Tree Selection each show how a row looks. Lazy loading, flipping upward, and opening inside a modal are shared, since those do not depend on how a row is drawn.

### Mixed values

When one field edits several records, such as a bulk edit, pass `mixedValues` with every value that some, but not all, of those records hold. Each one that isn't in `value(s)` gets a dot, and a legend at the top of the list explains it. A single select reads "Mixed" until a value is picked. A multi or tree select reads "Mixed" while any value is dotted. Its count badge then covers the dotted values too, but the pills stay selected-only. Checkboxes behave as usual: checking a dotted row selects it, and unchecking it brings the dot back. So keep `mixedValues` as loaded, and let `value(s)` carry the edit. Dots come from loaded options, so with `{ current, load }`, include the mixed options in `current`, and with `onSearch`, keep them in `options` alongside the selection.
